## 一、Markdown 公式渲染（LaTeX）

### 1.1 功能介绍

v2.0 集成 [KaTeX 0.16.11](https://katex.org/)，支持在 Markdown 中直接书写 LaTeX 数学公式，预览区会实时渲染。

### 1.2 语法说明

| 类型 | 语法 | 示例 | 渲染效果 |
| --- | --- | --- | --- |
| **行内公式** | `$公式$` | `质能方程 $E=mc^2$ 体现了...` | 公式嵌在文字中 |
| **块级公式** | `$$公式$$` | `$$\int_0^\infty e^{-x^2}dx = \frac{\sqrt{\pi}}{2}$$` | 居中独占一行 |

### 1.3 支持的公式类型

- **基础运算**：分数 `\frac{a}{b}`、根号 `\sqrt{x}`、上下标 `x^2_1`
- **微积分**：积分 `\int`、求和 `\sum`、极限 `\lim`、导数
- **矩阵**：`\begin{matrix}...\end{matrix}` 等多种矩阵环境
- **希腊字母**：`\alpha \beta \gamma \pi \theta` 等
- **符号**：`\infty \partial \nabla \forall \exists` 等
- **多行公式**：`\begin{aligned}...\end{aligned}` 对齐方程组

### 1.4 转义与注意事项

- 想要原样输出 `$` 符号：使用 `\$` 转义
- 公式语法错误时，预览区会显示红色提示：`[公式错误: ...]`
- 公式优先于 Markdown 解析，避免下划线、反斜杠破坏公式结构

### 1.5 示例

```markdown
## 泰勒展开

函数 $f(x)$ 在 $x=a$ 处的泰勒展开为：

$$
f(x) = \sum_{n=0}^{\infty} \frac{f^{(n)}(a)}{n!}(x-a)^n
$$

矩阵表示：

$$
A = \begin{pmatrix}
a_{11} & a_{12} \\
a_{21} & a_{22}
\end{pmatrix}
$$
```

### 1.6 PDF 导出公式

PDF 导出已同步支持 LaTeX 渲染，导出的 PDF 文档会保留公式的视觉效果。

## 二、全屏预览 + 笔刷标注

### 2.1 进入全屏预览

- 编辑器顶部切换为「预览模式」时，预览区会自动扩展为全屏
- 全屏后右上角显示 **退出全屏预览** 按钮（替代旧版的 ESC 退出）

> 💡 移动端同样支持全屏预览，体验已优化为更适合触屏操作。

### 2.2 笔刷标注工具

全屏预览时顶部浮动笔刷栏，提供以下工具：

| 工具 | 说明 | 快捷场景 |
| --- | --- | --- |
| **荧光笔** (highlight) | 半透明粗笔，画过文字下方高亮 | 重点标注段落 |
| **钢笔** (pen) | 不透明细笔，自由绘画 | 圈画、批注 |
| **讲解笔** (annotate) | 直线箭头，起点 → 终点 | 指向特定位置 |
| **橡皮擦** (eraser) | 点击删除已绘制的路径 | 清除单条标注 |
| **撤销** | 撤销最近一次绘制 | 误操作回退 |

### 2.3 笔刷属性

- **颜色**：点击色板选择预设颜色，或自定义任意颜色
- **粗细**：拖动滑块调整笔刷大小（1-30）

### 2.4 标注保存

- 标注数据自动保存到浏览器 `localStorage`（按日记 ID 隔离）
- 下次打开同一日记时自动恢复之前的标注
- 标注仅保存在本地浏览器，不会上传服务器，换设备需重新绘制
- 清除浏览器缓存会丢失标注

### 2.5 笔刷栏特性（已修复）

- ✅ 笔刷栏使用 `position: fixed` 浮动贴视口，滚动时不抖动
- ✅ 修复了标注坐标偏移问题（之前点击位置与绘制位置不一致）
- ✅ 修复了拖拽时的回弹问题

- **明暗模式**：浅色 / 深色 / 跟随系统

| --- | --- |

## 四、可见性预选

### 4.1 改进点

之前在编辑日记时，切换可见性为「指定用户」后，已勾选的用户列表不会自动回填。v2.0 已修复：

- 打开编辑弹窗时，**自动预选**当前日记已有的 `visibleTo` 列表
- 通过下拉框 change 事件实时同步勾选状态
- 切换可见性级别时不会丢失已选用户

### 4.2 操作流程

1. 编辑日记 → 点击「可见性」下拉
2. 选择「指定用户」
3. 弹出好友选择列表，**已选用户会自动勾选**
4. 增减用户后保存，下次打开仍保留最新选择

## 五、管理员：数据存储位置管理

### 5.1 功能介绍

v2.0 新增「数据存储位置」管理功能，管理员可将平台数据（数据库 + 上传文件）迁移到任意盘符或路径，解决系统盘空间不足的问题。

### 5.2 进入入口

管理后台 → 「系统性能」或「平台设置」→ 「数据存储位置」

### 5.3 查询当前存储位置

页面会显示：
- **当前数据库目录**：默认 `data/`
- **当前上传目录**：默认 `public/uploads/`
- **数据库大小**：当前 db 文件占用空间
- **上传文件大小**：当前 uploads 目录占用空间
- **可选盘符列表**：系统所有可用磁盘
- **是否为自定义路径**：标记是否已迁移

### 5.4 切换存储位置

1. 点击「切换存储位置」
2. 输入或选择目标路径（如 `D:\treeks-data`）
3. 系统会自动校验：
   - ✅ 目标路径可写
   - ✅ 不是项目根目录（避免误删源码）
4. 选择是否迁移现有数据：
   - **迁移**：复制现有数据库与上传文件到新位置
   - **不迁移**：仅切换路径，旧数据保留原位
5. 点击确认 → 执行迁移
6. **重启服务** 后生效

### 5.5 安全设计

- **复制而非移动**：迁移采用复制策略，原数据保留，便于回滚
- **路径校验**：禁止选择项目根目录、系统关键目录
- **配置持久化**：迁移路径保存在 `settings.storage_path`，重启自动恢复
- **操作日志**：所有切换 / 重置操作记录到管理员日志

### 5.6 恢复默认存储位置

如需恢复到项目默认目录：
1. 点击「恢复默认」
2. 系统会重新指向 `data/` 和 `public/uploads/`
3. **重启服务** 后生效
4. 自定义路径中的数据需手动迁回

### 5.7 容器部署支持

如使用 Docker 等容器部署，可通过环境变量预设：

```bash
TREEKS_RUNTIME_DB_DIR=/data/db
TREEKS_RUNTIME_UPLOAD_DIR=/data/uploads
```

设置后系统会跳过自动引导，直接使用环境变量指定的路径。

### 5.8 API 接口

```http
# 查询存储位置
GET /api/admin/system/storage-location
Authorization: Bearer <admin-token>

# 校验目标路径
POST /api/admin/system/storage-location/validate
Content-Type: application/json

{ "targetPath": "D:\\treeks-data" }

# 切换存储位置
POST /api/admin/system/storage-location
Content-Type: application/json

{
  "targetPath": "D:\\treeks-data",
  "migrate": true
}

# 恢复默认
POST /api/admin/system/storage-location/reset
```

## 六、编辑器体验改进

### 6.1 模态框交互修复

**修复前**：点击确认按钮后弹窗不关闭，导致后续所有按钮失效，必须刷新页面。

**修复后**：
- 点击确认 / 取消后弹窗自动关闭
- 按钮状态正确恢复（disabled 解除）
- 支持连续打开多个弹窗

### 6.2 自动保存改进

- 协作者弹窗、发信件弹窗打开前会先触发自动保存
- 避免在弹窗操作中丢失正在编辑的内容
- 保存失败时弹窗不会打开，并显示错误提示

### 6.3 新建日记覆盖 bug 修复

**严重 bug 描述**：在未保存当前日记的情况下点击「新建日记」，新日记会覆盖原日记的内容，导致数据丢失。

**修复方案**：
- 新建前检测当前日记是否有未保存修改
- 弹出确认对话框：「当前日记尚未保存，是否丢弃？」
- 选择「丢弃」才创建新日记
- 选择「取消」则保留在当前编辑界面

## 七、跨时区时间显示修复

### 7.1 问题表现

v1.0 中时间显示存在严重偏移：
- 日记创建时间显示 8 小时前
- 信件接收时间显示 8 小时前
- 新注册用户的注册时间显示 8 小时前
- 日历显示的日记日期与实际日期错位一天

### 7.2 根因

服务器时区与 UTC 存在偏移，但代码混用了 `toISOString()`（UTC）和 `localtime`，导致时间计算错误。

### 7.3 修复方案

- **统一存储**：所有时间字段统一以 UTC 时间存储
- **统一显示**：前端读取时统一通过本地时区转换
- **日历处理**：`routes/diaries.js` 使用本地日期字符串（`localDateStr`）而非 UTC 日期，避免跨日错位

### 7.4 验证

修复后验证：
- ✅ 新发送的信件立即显示「刚刚」
- ✅ 新建日记的创建时间为当前时间
- ✅ 日历点击当日显示当日所有日记

### 7.5 部署建议

为确保时间显示正确，建议服务器设置正确时区：

```bash
# Linux
export TZ=Asia/Shanghai

# Windows：默认使用系统时区，无需额外设置

# Docker
docker run -e TZ=Asia/Shanghai ...
```

## 八、升级指南

### 8.1 从 v1.0 升级到 v2.0

```bash
# 1. 备份数据
cp -r data/ data.backup/
cp -r public/uploads/ public/uploads.backup/

# 2. 拉取最新代码
git pull origin main

# 3. 安装新依赖（如有）
npm install

# 4. 重启服务
npm start
# 或
pm2 restart treeks
```

### 8.2 数据库自动迁移

v2.0 启动时会自动处理数据库 schema 兼容：
- 旧 `theme` 字段值自动解析为新格式
- 新增 `settings.storage_path` 字段（如不存在则自动创建）
- 不需要手动执行 SQL 迁移脚本

### 8.3 浏览器缓存清理

升级后请**强制刷新浏览器**（Ctrl + F5），以加载新的 CSS / JS 资源。

### 8.4 升级后检查清单

- [ ] 登录正常，主题显示正确（旧主题自动迁移）
- [ ] 日记创建时间显示正确（无 8 小时偏移）
- [ ] 日历点击当日显示当日日记
- [ ] 公式渲染正常（试写 `$E=mc^2$`）
- [ ] 全屏预览笔刷标注可用
- [ ] 模态框可连续打开（点击确认后正常关闭）
- [ ] 新建日记不会覆盖未保存的旧日记

### 8.5 回滚方案

如升级出现问题需回滚到 v1.0：

```bash
# 1. 停止服务
pm2 stop treeks

# 2. 恢复代码
git reset --hard <v1.0-commit-hash>

# 3. 恢复数据
rm -rf data/ public/uploads/
mv data.backup/ data/
mv public/uploads.backup/ public/uploads/

# 4. 重启
pm2 restart treeks
```

2. 在笔刷栏 HTML 中添加对应按钮
3. 在 `setBrushTool()` 中处理激活状态
4. 在 `createPathElement()` 中实现绘制逻辑
